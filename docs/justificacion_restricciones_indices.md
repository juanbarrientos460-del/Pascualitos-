# Justificación de restricciones e índices

## Llaves primarias (PK)
Cada tabla tiene una PK estable. Las tablas de catálogo y entidades usan identificadores sustitutos generados por identity, excepto codigo_paro, cuyo número oficial funciona como clave natural. registro_persona usa PK compuesta (id_registro,id_persona) para impedir asociar dos veces a la misma persona al mismo registro.

## Llaves foráneas (FK)
- registro_produccion → maquina, turno y referencia: evita registros asociados a catálogos inexistentes.
- subcodigo → codigo_paro y subcodigo padre: mantiene la jerarquía dentro del mismo código.
- registro_persona → registro_produccion y persona: garantiza que ambos extremos existan.
- paro → registro_produccion, codigo_paro, subcodigo y persona: evita eventos huérfanos y subcódigos de un código diferente.

## ON DELETE / ON UPDATE
- Catálogos referenciados por producción/paros: ON DELETE RESTRICT, para conservar historia y evitar borrar dimensiones utilizadas.
- registro_produccion → paro y registro_persona: ON DELETE CASCADE porque esos detalles no tienen sentido sin su registro padre.
- registro_persona → persona: ON DELETE RESTRICT para preservar trazabilidad.
- ON UPDATE CASCADE en relaciones para mantener integridad si se modifica una clave; las PK identity y códigos históricos no deberían modificarse normalmente.

## UNIQUE
- maquina.nombre y turno.descripcion: evita duplicar líneas y turnos.
- persona.codigo_anonimo: evita códigos de persona repetidos.
- referencia(producto,volumen_cc,num_colores): evita repetir la misma presentación.
- subcodigo(num_codigo,codigo_texto): la clave de subcódigo solo debe ser única dentro de su código.
- registro_persona(id_registro,id_persona): evita asociaciones duplicadas.

## CHECK
- persona.rol y paro.ejecutor_tipo: solo valores de dominio aprobados.
- referencia.volumen_cc y num_colores: positivos cuando se informan.
- registro_produccion.pacas_producidas y horas_trabajadas: no negativos; meta_por_hora positiva.
- paro.minutos: estrictamente positivo.
- La FK compuesta de paro valida que id_subcodigo corresponda al num_codigo indicado.

## NOT NULL y DEFAULT
NOT NULL se usa donde un dato es obligatorio para interpretar el hecho: fecha y máquina en producción; registro, código y minutos en un paro; claves de catálogos y relaciones. Los campos históricos incompletos admiten NULL para no inventar información. Los identificadores usan GENERATED BY DEFAULT AS IDENTITY. No se asigna DEFAULT 0 a cantidades faltantes porque NULL significa desconocido/no informado, no cero.

## Índices y consultas que aceleran
| Índice | Uso esperado |
|---|---|
| ix_registro_fecha(fecha) | Rangos de fechas y reportes por período. |
| ix_registro_maquina_fecha(id_maquina,fecha) | Productividad mensual/anual por máquina. |
| ix_registro_turno_fecha(id_turno,fecha) | Comparación por turno y período. |
| ix_paro_codigo(num_codigo) | Participación de cada código de paro. |
| ix_paro_registro(id_registro) | JOIN de paros con registro de producción. |
| ix_paro_subcodigo(id_subcodigo) | Análisis por subcódigo. |

Los índices se deben validar con EXPLAIN (ANALYZE, BUFFERS) sobre el volumen real. Un índice no garantiza una mejora si la tabla es pequeña o el filtro no es selectivo.
